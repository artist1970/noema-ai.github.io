# NOEMA — Protected Administrative Intelligence Runtime for NAIB

**NOEMA** is the protected administrative intelligence runtime that supports **NAIB**, the public Administrator for the Verve N Veda ecosystem.

This repository is **not the canonical public NAIB identity** and it is **not a STOS authority plane**. It provides the governed runtime behind NAIB: memory and cloud services, specialist federation, research and evidence support, provider boundaries, orchestration, privacy controls, capability checks, and proposal mediation.

## Architectural Role

The distinction between **NAIB** and **NOEMA** is intentional.

### NAIB

NAIB is the public-facing **Administrator**.

NAIB owns the visible experience:

- public identity and presentation
- conversation presentation
- user-facing task organization
- visible plans and next steps
- specialist handoff presentation
- resource discovery
- public guidance
- voice and interaction surfaces

### NOEMA

NOEMA is the protected **Chancellor / administrative intelligence layer** behind that public experience.

NOEMA owns or governs:

- constitutional and policy boundaries
- capability and permission checks
- memory governance
- internal cloud coordination
- identity and guardian pathways
- evidence and verification rules
- specialist eligibility and routing support
- research and source handling
- provider security boundaries
- privacy controls
- account/server seams
- orchestration and checkpoint infrastructure
- audit, trace, and receipt support

**NAIB may ask NOEMA for a governed capability. NAIB may not become NOEMA.**



The runtime may inspect, reason, organize, retrieve, compare, prepare, and propose within its allowed boundaries.

It does **not** obtain execution authority merely because an AI, specialist, model, memory record, or internal service recommends an action.


The boundary is **proposal-only**.

It may represent bounded requests such as:

- health or status inspection
- repository or knowledge reads
- evidence and research requests
- specialist hints
- analysis requests
- plan generation
- proposed next actions

It does **not** permit ADIT to:

- execute shell commands
- enter terminal input
- mutate repositories
- write directly to NAIB memory
- write directly to the NAIB Internal Cloud
- start, stop, or restart runtimes
- obtain administrator authority
- access secrets or credentials
- self-elevate permissions
- bypass STOS policy
- proxy the normal STOS Gateway directly


Its current namespaces include areas for:

- artifacts
- attachments
- conversation archive
- evidence
- exports
- federation cache
- learning
- memory archive
- portfolio
- projects
- research
- system records

## Research, Evidence, and Verification

NOEMA is designed to preserve distinctions among:

- source material
- retrieved evidence
- verified information
- unverified information
- inference
- interpretation
- recommendation
- proposed action
- completed action

AI-generated text is not evidence merely because an AI generated it.

A result should not be described as completed, submitted, published, sent, purchased, scheduled, verified, or otherwise executed unless the runtime has evidence supporting that status.

## User and Human Authority

Human authority remains final.

NAIB and NOEMA may:

- explain
- organize
- compare
- recommend
- retrieve
- summarize
- prepare
- propose

They may not silently convert assistance into authority.

Permission self-elevation is prohibited.

## Privacy and Provider Boundaries

Public browser code must not contain:

- API keys
- database passwords
- administrator credentials
- private provider secrets
- hidden bearer tokens
- protected STOS credentials

Provider credentials belong behind approved secure server boundaries.

The runtime is designed so that public surfaces can know safe provider status and normalized responses without embedding protected credentials in browser storage.

## Design Principles

NOEMA follows a few non-negotiable rules:

1. **Public identity and protected governance remain separate.**
2. **Memory may influence attention, not authority.**
3. **Specialists remain distinct.**
4. **A proposal is not an execution.**
5. **Evidence and inference must remain distinguishable.**
6. **Secrets never belong in public browser code or continuity records.**
7. **Historical artifacts are provenance, not automatically current authority.**
8. **Consequential actions remain subject to STOS authorization.**
9. **The human operator remains the final decision-maker.**
10. **Sovereign components should remain replaceable without collapsing identity, memory, or governance into a single model provider.**
