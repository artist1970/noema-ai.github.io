# NAIB + NOEMA Architecture

## Identity separation

```text
HUMAN
  ↓
NAIB
Public Intelligence Director
  ↓
NOEMA
Administrative Intelligence
  ↓
Constitution · permissions · memory · identity · Verifier · security · specialists
```

NAIB is the public conversational identity.

NOEMA is not deleted or renamed. It remains the administrative intelligence layer.

## Why this matters

The system no longer asks one identity to be both:
- warm, direct, conversational and public; and
- administrative, security-sensitive, policy-governing and infrastructure-oriented.

NAIB can remain understandable and personable.

NOEMA can remain strict, durable and administrative.

## Public authority

NAIB may:
- converse;
- explain;
- plan;
- coordinate;
- present Verifier status;
- use permitted memory and mentor context;
- prepare specialist handoffs.

NAIB may not:
- elevate permissions;
- modify authentication;
- override guardian rules;
- override the Constitution;
- bypass The Verifier;
- silently write long-term memory;
- impersonate NOEMA administration.

## Data continuity

Existing local keys remain unchanged:

```text
noema_*
```

This is intentional.

Those keys now represent NOEMA-managed administrative storage rather than public brand identity.

There is no destructive migration.
